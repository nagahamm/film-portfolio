# 詳細設計

**いま構造がどうなっているか**を書く。変更の理由や経緯は Issue とコミットに残し、ここには残さない。
構造に関わる変更は、実装より先にここを更新する。

見た目(色・タイポグラフィ・コンポーネントの意匠)は
`.claude/skills/portfolio-design/` が持つ。ここでは扱わない。

## 全体像

WordPress で編集し、静的な HTML に書き出して Netlify から配信する。
WordPress は持ち主の PC(Local)の中だけで動き、公開されない。
公開中のサイトは今までどおり**ビルド工程もサーバー側の処理も持たない静的サイト**であり、
管理画面・データベース・PHP は本番に存在しない。

```
持ち主の PC                                   本番
  Local(WordPress)                           Netlify
    ├── テーマ = このリポジトリ ──┐            ├── site/ の HTML・CSS・JS・画像・PDF
    └── Secure Custom Fields ─────┤ 書き出し ─→   (netlify.toml のヘッダ・リダイレクト)
  scripts/export-site.mjs ────────┘  → site/   └── 動画だけは R2 へ 302
```

- 編集: 管理画面で作品・本文・メディアを入力する
- 書き出し: `scripts/export-site.mjs` が作品一覧からリンクをたどって全ページを巡回し、`site/` に静的ファイルとして保存する
- 公開: `scripts/publish.sh` が検証を通したうえで `site/` を Netlify へ送る

道具は編集側(PC)にだけ置き、本番には持ち込まない。「手元では動くが本番と違う」を防ぐため、
本番の正しさは必ず書き出し結果 `site/` に対して確かめる(`## 検証`)。

`wp-content/themes/film-portfolio` からこのリポジトリへシンボリックリンクを張る。
`css/style.css` と `js/main.js` は場所を変えない。

## 責務の分離

| 層 | 担当 | 触ってはいけないこと |
| :--- | :--- | :--- |
| 入力欄(管理画面) | 本文・メディア・並び順・セクションの表示/非表示 | 構造や装飾(HTML・クラスを入力させない) |
| `template-parts/*.php` | 構造。入力値を既存のクラス・属性に流し込む | 装飾(インラインスタイル禁止)、本文の直書き |
| `css/style.css` | 装飾のすべて | — |
| `js/main.js` | 状態の切り替え | スタイル値の直接指定(状態クラスを付けて CSS に委ねる) |

テンプレートは、CSS と JS が前提にしている**クラス・属性・入れ子**を崩さずに出力する。
CSS と JS は HTML の形にだけ依存しているため、形が同じなら入力値が変わっても動く。
JS が見ているフックは `.claude/skills/portfolio-design/references/components.md` にまとめてある。

JS が CSS の値を直接書き込む例外は `--masonry-gutter` の読み取りのみ。
これは CSS 側を唯一の定義とし、JS がそれを読む向きに固定している。逆向きにしない。

## CSS の構造

1. `DESIGN TOKENS`(`:root`) — 色・比率・寸法・モーションの唯一の定義
2. `RESET & BASE` → `TYPOGRAPHY PRIMITIVES` — 全体の土台
3. コンポーネント各節 — **ページの登場順**に並べる
4. `UTILITIES` → `RESPONSIVE` — 最後

新しい節を足すときは登場順の位置に挿入する。末尾に足していくと対応関係が崩れる。

## JS の構成

`js/main.js` は上から順に、独立した小さなブロックの列として並ぶ。相互に状態を共有しない。

| ブロック | 目印 | 役割 |
| :--- | :--- | :--- |
| フェードイン | `.fade` | スクロール連動の表示。IntersectionObserver |
| Masonry | `.masonry-grid` | 高さの揃わない写真の配置 |
| アルバム割り当て | `[data-album]` | 拡大表示のグループ分け |
| カルーセル | `[data-carousel]` | Episode / Craft 共通。2枚以上のときだけ |
| ミュート切替 | `.ep-video-mute` | 音声のオン/オフ |
| 画面内再生 | `.carousel-slide video` | 見えている動画だけ再生 |
| 比較スライダー | `[data-compare]` | Before/After |
| ショットリスト | `.shotlist-marquee` | 横ドラッグ |
| メディアモーダル | `#img-modal` / `#video-modal` / `#film-modal` | 拡大表示 |

新しい振る舞いは既存ブロックに混ぜず、独立したブロックとして足す。

## メディアモーダル

このサイトで最も込み入っている箇所。**先に読むこと。**

### アルバム
`[data-album]` を持つ `img` / `video` を DOM 順にグループ化する。写真と動画が混在しても
1本の連続した並びとして前後送りできる。同じ `src` は重複排除される。

### 枠 — `.modal-frame` と `.modal-stage` の役割分担
2枚の枠を意図的に分けている。**取り違えると効かない。**

| 要素 | 役割 | 付くクラス |
| :--- | :--- | :--- |
| `.modal-frame` | 閉じる・左右ボタンの**位置基準**(`position:relative`)。幅はアルバム全体に合わせる | `.is-portrait-frame` / `.is-landscape-frame` |
| `.modal-stage` | 表示中メディアの**比率の固定枠** | `.is-portrait-modal` / `.is-landscape-modal` |

比率は表示中の1枚ごとに変わるが、ボタンは前後送りで動いてはいけない。
そのため frame はアルバム内に1枚でも横構図があれば広い側に固定し(`setFrames`)、
一度広げたら同じアルバムを見ている間は縮めない(`widenFrames`)。
stage だけが1枚ごとに切り替わる。

### ボタン位置
`--modal-btn-x` / `--modal-btn-y` の **符号だけ** で枠の内/外が切り替わる
(負=枠外・PC、正=枠内・モバイル)。個別セレクタで位置を上書きしない。

### 音
モーダル内で音の状態を引き継ぐ(`modalMuted`)。既定は音あり。一度消したら
以降に開く動画も消音で始まる。前後送りのたびに音が鳴り直さないための設計。

### キーボード
開閉のたびにリスナーを登録し直さず、`isOpen()` で判定する常設リスナーにしている。
二重発火を防ぐため。全画面中はネイティブのシーク操作を優先し、左右キーを奪わない。

### 本編 (`#film-modal`)
Instagram の埋め込み(`iframe`)。先方が iframe 内にヘッダーとフッターを描き、
残った領域へ動画を 9:16 で収める。つまり**動画の描画幅は高さ側から決まる**ため、
幅を固定値で置くと差がそのまま左右の黒帯になる。`--modal-embed-w` は
利用可能な高さから逆算する `clamp()` 式で、`--modal-embed-chrome`(先方UIの実測値)を
引いてから 9/16 を掛ける。Instagram 側のデザインが変わったら要調整。比率判定の対象外。
埋め込み URL は入力させず、本編の URL(`/reel/<ID>/`・`/reels/<ID>/`・`/p/<ID>/`)の ID から
`https://www.instagram.com/reel/<ID>/embed/` を作る。
埋め込みが再生できない場合に備え、自己ホストの本編(`#modal-video-player` の `src`)を
フォールバックとして持つ。

## 作品のデータ

作品1件 = 投稿タイプ `work` の投稿1件。URL は `/works/<slug>/`。
一覧の並び順は投稿の「順序」で決め、下書きは書き出されない。

### 作品の基本項目

| 項目 | 用途 |
| :--- | :--- |
| タイトル | 見出し・一覧のカード。`<title>` は「ページのタイトル」があればそれ、無ければ「<作品名> — SHORT FILM PORTFOLIO 光輝」 |
| 抜粋 | `<meta name="description">` |
| 差し色 | 作品ごとの `--rust` 系の振り分け(選択式) |
| ヒーロー | 肩書き(eyebrow)・ジャンル・リード文。作品名の下の行は「<ジャンル> / <尺>」をテンプレートが組む(尺は本編の尺を使い、2か所に入れさせない) |
| 本編 | 本編の URL(フッター。Instagram の埋め込み URL もここから作る)、自前の本編動画(メディアライブラリから選ぶ)、ポスター(本編カード・一覧のカード)、尺 |
| ロケ地 ※ | ロケ地名と Google Maps URL(本文の自動リンク用) |

ヘッダーのサイト名は作品一覧(`/`)へのリンク。ナビは作品ページにだけ出し、表示するセクションから(ページの順。Next はナビに出さない)作る。フッターの「作品を観る」は
本編の URL から作る。作品ページ以外では、フッターは一覧の先頭の作品の本編へリンクする。

### セクション(省略できる部品)

管理画面ではセクションごとにタブを分け、中身はタブと同じ名前のグループ(`watch` など)に入れる。
ページに出る順は固定(下の表の順。`inc/sections.php` の `FP_SECTIONS`)で、並べ替えはできない。
各グループの「このセクションを表示する」(`enabled`)がオフのセクションは見出しごと出力されず、
ヘッダーのナビにも出ない。グループと既存のセクションは1対1で、新しい種類は既存コンポーネントで描けるものに限る。

| タブ | グループ名 = `id` | 中身(繰り返しは ※) |
| :--- | :--- | :--- |
| Watch | `watch` | ショットリスト画像(ギャラリー)、実績カード ※(数・単位・補足・リンク) |
| Slate | `slate` | 作品概要カード ※(ラベル・値)。先頭の Title・Runtime は作品名と尺からテンプレートが作る。値が2行以上なら1行1項目の箇条書き、1行なら文 |
| Craft | `craft` | 担当カード ※(ラベル・比率の種類・説明・写真(ギャラリー)) |
| Approach | `onset` | 課題・対策・成果の行 ※(役割・3列の本文) |
| Process | `process` | 時期 ※(時期・見出し・本文・エピソード ※(見出し・メディア ※・比較スライダー・本文)) |
| Materials | `materials` | リード文、資料カード ※(ラベル・英語ラベル・PDF・リンク語) |
| Next | `next` | 課題・改善の行 ※(役割・2列の本文) |

- 見出し・eyebrow・表の列名など、作品によって変わらない文言はテンプレートに置く。
- メディア ※ の1件はファイル、この場所だけの写真の説明(任意)、キャプションを持つ。写真か動画かはファイルの種類で決める。
  動画のポスターは同じベース名の `-poster.jpg`、音声の有無は動画の音声トラックの有無
  (アップロード時に WordPress が読み取る情報)で決め、音声ありの動画にだけミュートボタンを出す。
- 写真の説明(読み上げ用)は、メディアライブラリで写真ごとに入れる「代替テキスト」(`_wp_attachment_image_alt`)を使い、
  入力欄には持たない(`fp_alt()`)。同じ写真でもセクションによって役割が違うときに備え、Process のメディアにだけ
  この場所だけの説明を残し、入っていればそちらを使う。
- 説明もキャプションも持たない写真の並び(ショットリスト・Craft の写真)は、まとめて選んで並べ替えるギャラリー欄にする。
- ほかの入力値から決まるもの(埋め込み URL・ポスター・音声の有無・作品概要の作品名と尺、作品概要カードの文か箇条書きか)は入力させない。
- 入力欄の説明は執筆者向けに、ページのどこに出るかと例で書く。ファイルの場所・配信先・形式名など開発の話は書かない。
  管理画面は説明を HTML として扱うため、`<` `>` は使わない(書式の見本は具体例で示す)。
- Craft の「比率の種類」は既存の `data-label`(Camera / Color / Edit など)にそのまま出力し、
  CSS の比率の例外が従来どおり効くようにする。

### 差し色

インラインスタイルを使わないため、色の値は入力させない。`css/style.css` に差し色の組を
クラス(`.accent-<名前>`)として定義し、入力欄はその名前を選ぶだけにする。
`single-work.php` は選ばれたクラスを `<body>` に付ける。色を足すときは CSS に組を1つ足し、
`inc/accent.php` の選択肢に名前を足す。

## 本文の書式

- 本文・キャプションの入力欄はテキストエリア(改行 → `<br>`)。WordPress の自動整形
  (`wpautop`・`wptexturize`)は止め、入力した文字をそのまま出す。
  記号(`—` `…` `「」`)が勝手に置き換わらないようにするため。
- リンクは入力させない。表記ルールの「本文中の特定語の自動リンク化」は
  `inc/autolink.php` が出力時に行う。辞書は次の3つを合わせたもの。
  - サイト共通: Instagram
  - 作品の資料カード: カードの「リンク語」(ショットリスト・香盤表など) → そのカードの `id`
  - 作品のロケ地: ロケ地名と Google Maps URL の組 ※(作品の基本項目に持つ)
- ページ内アンカー(資料カードへのリンク)には常に `.inline-link` を付ける。外部リンク(地図・Instagram)は、
  リンク色をセクション側で持たない暗背景のセクション(Next)でだけ付ける。Slate・Process は
  セクションの CSS がリンク色を持つため付けない。どちらにするかはテンプレートが `fp_text()` に渡す。
- 資料カードのラベルなど、`fp_text()` を通らない文字はリンクにならない。

## メディアの配信

| 種類 | 原本 | 本番の経路 |
| :--- | :--- | :--- |
| 画像・PDF | `uploads/<作品の slug>/`(メディアライブラリ。Git には入れない) | 公開時に **Cloudflare R2 の `uploads/<作品の slug>/`** へ送り、`netlify.toml` の 302(`/wp-content/uploads/*` → R2)で配信 |
| 動画 | `uploads/<作品の slug>/`(メディアライブラリ。Git には入れない) | 公開時に **Cloudflare R2 の `videos/<作品の slug>/`** へ送り、`netlify.toml` の 302(`/assets/videos/*` → R2)で配信 |

- 画像の自動縮小・別サイズの生成は止める。原本のファイル名のまま1枚だけ置く。
- アップロード先は年月ではなく作品ごとのフォルダにする(`inc/media.php`)。
- ファイル名の規則(`YYYY-MM-DD__種別_連番__slug`)はアップロードする前に守る。
  同名のファイルを上げると WordPress が連番を付けてしまうため、内容を差し替えるときは
  ファイル名を変えてから上げる。
- 画像・PDF・動画はすべて管理画面からメディアライブラリへ上げ、入力欄で選ぶ。
  Git には入れない(履歴を実質不可逆に膨らませるため)。本番は Netlify 上のファイルではなく R2 から配信する。
- 画像・PDF の URL は WordPress どおり `/wp-content/uploads/<作品の slug>/<ファイル名>`。
  R2 の置き場所(`uploads/<作品の slug>/<ファイル名>`)も同じ相対パスにそろえる。
- 動画のテンプレート(`fp_video()`)は、メディアライブラリ上の置き場所をそのまま使って
  `/assets/videos/<作品の slug>/<ファイル名>` を出力する。
  R2 の置き場所(`videos/<作品の slug>/<ファイル名>`)も同じ形にそろえる。
- R2 へは公開の最初に `scripts/sync-media.mjs` が送る。メディアライブラリを R2 と突き合わせ、
  無いもの・サイズが違うものだけを送る。動画は送る前に映像が H.264 かを確かめ、違えば止める。
  R2 から消すことはしない(差し替えはファイル名を変えて上げる運用のため)。
- リダイレクトは種類ごとにワイルドカード1本なので、ファイルを足しても `netlify.toml` は変えない。
  Local では画像・PDF はそのまま `wp-content/uploads` から出し、動画だけ nginx
  (`~/Local Sites/<サイト>/conf/nginx/site.conf.hbs`)で `/assets/videos/*` を
  手元の `wp-content/uploads/*` へ振り向ける。R2 へ送る前の動画も確認用の表示で再生できる。
  R2 への送り漏れは `scripts/check.mjs --site` が検出する。
- 書き出し(`export-site.mjs`)は画像・PDF・動画を `site/` に複製しない(本番はリダイレクトで足りる)。
- インライン動画のポスターは画像としてメディアライブラリに上げ、
  動画と同じベース名に `-poster` を付ける。テンプレートはこの名前からポスターの URL を作るため、
  入力欄では選ばない。上げ忘れは書き出しの段階で止まる(参照先が見つからない)。

## キャッシュ

`/wp-content/uploads/*` は1年(`netlify.toml`)。ファイル名に撮影日と用途を含み、
内容が変わればファイル名も変わる運用が前提。**同じ名前のまま中身を差し替えてはいけない。**
テーマ(`/wp-content/themes/*`)の `css/` と `js/` は1時間。

## レスポンシブ

ブレークポイントは `48em` と `30em` の2つのみ。3つ目を作らない。
`48em` 以下では Grid / Subgrid / 中央揃えを完全にリセットして縦積みにする。

## 書き出しと公開

1. 管理画面で編集を終える
2. `scripts/publish.sh` を実行する(`--dry-run` を付けると公開の手前で止まる)
   1. `node scripts/sync-media.mjs` で R2 に無いメディア(画像・PDF・動画)を送る
   2. `node scripts/export-site.mjs` で `site/` に書き出す
   3. `node scripts/check.mjs --site` で検証する。失敗したら止まる
   4. `scripts/export-content.sh` で本文を `data/portfolio.sql` に書き出す
   5. `npx netlify-cli deploy --prod --dir=site` で公開する
3. `data/portfolio.sql` の変更をコミットする(メディアの実体は R2。Git には入れない)

書き出しは自前の `scripts/export-site.mjs` で行う。作品一覧からサイト内のリンクをたどり、ページと
参照されている CSS・JS だけを保存し、URL をルート相対(`/…`)に置き換える。画像・PDF・動画は
R2 へ振り向けるため `site/` には入れない。案内ページは存在しない URL への応答を `404.html` として
保存する(Netlify が自動で使う)。WordPress の書き出しプラグインはコマンドから実行できず、
公開を1本の手順にまとめられないため使わない。

リポジトリは公開のため、ユーザー・設定(`wp_users`・`wp_usermeta`・`wp_options` 等)のテーブルは
書き出さない。管理者のメールアドレスやパスワードのハッシュを含むため。復元するときは Local で
新しいサイトを作り、テーマとプラグインを有効にしてから `data/portfolio.sql` を取り込む。

### 手元の編集環境を戻す

`data/portfolio.sql`(GitHub)・写真・PDF・動画(いずれも R2)で中身はすべて揃うため、費用をかけずに戻せる。
手作業は Local のサイト作成だけにし、残りは `node scripts/restore.mjs` が行う。

1. Local でサイトを作る(ドメイン `film-portfolio.local`。管理者のアカウントはここで決める)
2. `node scripts/restore.mjs` を実行する
   1. Local のサイトの `wp-content/themes/film-portfolio` と `wp-content/uploads` をリポジトリへのリンクにする
      (中身のある実フォルダなら止まる)
   2. Local の nginx の設定に `/assets/videos/*` の振り向けが無ければ足す(反映には Local でサイトを再起動する)
   3. Secure Custom Fields を入れて有効にし、テーマを有効にし、パーマリンクを `/%postname%/` にする
   4. `data/portfolio.sql` を取り込む。作品がすでにあるサイトでは、`--force` が無ければ取り込む前に止まる
   5. メディアライブラリのうち手元に無いファイルを、R2 の公開 URL(`netlify.toml` の振り向け先)から取る。
      動画は `videos/`、画像・PDF は `uploads/`。サイズが R2 と違えば止まる
3. 公開には `npx netlify-cli login` と `npx netlify-cli link`(既存のサイトを選ぶ)、
   R2 へ送るには `npx wrangler@4 login` を済ませる

Netlify は Git 連携でのビルドを止め、公開は CLI からのみ行う。`netlify.toml` は CLI の
公開でも読まれるため、ヘッダとリダイレクトの定義はそのまま使える。

## 検証

`node scripts/check.mjs`(依存パッケージなし)。次の2段に分ける。

| 対象 | いつ | 見るもの |
| :--- | :--- | :--- |
| テーマ | コミットの前(常に) | PHP の構文(`php -l`)、JS の構文(`js/main.js`・`scripts/*.mjs`)、未定義の CSS 変数、テンプレートへのインラインスタイルの混入、インライン動画の必須属性、`acf-json/` が JSON として読めること・ラベルと説明に `<` `>` が無いこと、`uploads/` のファイル名がアセット命名に沿うこと |
