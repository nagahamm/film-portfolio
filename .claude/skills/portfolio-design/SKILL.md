# ポートフォリオのデザインシステム

ショートフィルム「エル・ドラド」の制作記録サイト。**フィルムの色を紙に焼き付けたような質感**が
このサイトの核で、これを損なう変更は入れない。

## 最初に守ること

1. **トークンを経由する。** 色・比率・寸法・モーションの生の値を CSS に直書きしない。
   必要な値が無ければ「新しいトークンを足す」のであって、その場に数値を置くのではない。
   定義場所は `css/style.css` 冒頭の `:root` ただ一箇所(`DESIGN TOKENS` 節)。
2. **既存トークンで足りるか先に確かめる。** 似た色・似た間隔を増やすのがトーンの崩れ方の
   ほとんど。`references/tokens.md` の一覧を見てから足す。
3. **セレクタはフラットに。** ネストを増やさず、`.block__element` 的な深い入れ子も作らない。
   既存は「コンポーネント名 + 状態クラス(`.is-*`) + データ属性(`[data-*]`)」で表現している。
4. **インラインスタイル禁止。** 装飾は必ず `css/style.css` へ。JS は状態クラスの付け外しだけを行う。
5. **変更したら `node scripts/check.mjs` を通す。** 未定義トークンやインラインスタイルの
   混入はここで落ちる。

## 変更の型ごとの手順

### 色を足す・変える
`references/tokens.md` の Palette / Text / Lines & scrims を読む。役割名で選ぶこと
(`--rust` は「差し色」、`--sand` は「紙」)。生の16進数を書かない。
暗い面には `--text-lo` 系、明るい面には `--text-hi` 系を使う。メディアに重ねる文字だけは
`--text-on-media` と `--scrim` の組み合わせを使う。

### コンポーネントを足す
1. `references/components.md` に同種のものが無いか探す。カルーセル・Masonry・比較スライダー・
   PAR テーブルは複数セクションで使い回している。まず再利用を検討する。
2. 新規なら `css/style.css` の対応セクション(`/* ===== 名前 ===== */` の区切り)に追記する。
   節の順序はページの登場順に揃える。
3. メディアを含むなら比率は `--ratio-inline` 等を使う。CLAUDE.md の
   Media Aspect Ratio Rules が優先する。

### 余白・寸法を変える
`--section-pad`, `--wrap-max`, `--measure`, `--header-height` が全体の骨格。
個別セクションで上書きするのではなく、まずこれらで足りないか考える。
`--measure`(37.5rem)は本文の可読幅で、日本語の行長として調整済み。安易に広げない。

### レスポンシブ
ブレークポイントは `48em` と `30em` の2つだけ。3つ目を作らない。
`48em` 以下では Grid / Subgrid / 中央揃えを完全にリセットして縦積み(Flexbox)にする。
新しいコンポーネントを足したら必ず `RESPONSIVE` 節にも縦積みの指定を書く。

## 参照

- `references/tokens.md` — 全デザイントークンと使いどころ
- `references/components.md` — コンポーネント一覧と使い回しの関係
- `docs/design.md` — 構造・モジュール責務(見た目ではなく仕組み)
- `CLAUDE.md` — 比率・動画・タイポグラフィの必須ルール(このスキルより優先)

## 拡張のしかた

このスキルは参照ファイルを足して育てる。SKILL.md 本体は手順だけに保ち、
一覧や詳細は `references/` に置く。パターンが増えたら:

- 新しいコンポーネント群 → `references/components.md` に追記
- トークンの追加 → `references/tokens.md` に追記(役割の説明を必ず書く)
- 独立した大きな主題(例: 印刷用スタイル、アニメーション設計) →
  `references/<主題>.md` を新設し、この節からリンクする
